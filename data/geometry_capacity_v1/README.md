# Geometry Capacity v1：几何表示与线性约束的机制实验

本批数据用于检验一个限定命题：**在相同原始通道负载、冷却额度和任务条件下，一个联合风险锥能准确表示弯曲容量边界；有限条线性约束需要在误放、误拦和表示复杂度之间取舍。** 同时检验耦合、当前状态、冷却额度与修复的作用。

这不是经真实设备校准的环境，也不是完整 DAFR / AgentDojo 端到端评测。四个 controller 名称使用同一个抽象热容量模型，不应当作为四个真实领域泛化结果。它适合作为机制实验附表；完整方法消融应与仓库已有 AgentDojo 消融分开报告。

## 数据如何构造

共有 360 个独立基础场景，每个派生 6 个配对变体，共 2,160 条。训练、开发、测试各 720 条，同一基础场景及其全部变体始终在同一集合。测试集包含 600 条二次容量场景与 120 条线性控制场景。随机种子固定为 20261011，无随机种子搜索。

动作是三通道分配向量 q。环境具有混合矩阵 L、背景负载 b、容量 R 和当前冷却额度 c，实际通道电流为 I=b+Lq。模拟温度 T=ambient+gain×ΣI²，允许上限为 ambient+gain×(R+c)²。线性控制场景将平方和替换成通道和，同时改变上限公式。安全标签来自独立模拟器对原始动作的执行结果，而非某个算法的判断。成功还必须满足最低吞吐量、分配上限和锁定字段。

参数范围：L 对角项 0.65–1.3，非对角项 0.03–0.3；初始背景负载 0–0.2；R 为 0.9–1.3；c 为 0–0.7；吞吐权重 0.7–1.3；最低吞吐量为原任务请求的 45%–80%。历史负载比当前低 0.03–0.15，截断至非负值。温度环境参数仅作单位映射，不提供经验标定。

每个基础场景含 natural、no_cooling、extra_cooling、concurrent_load、locked、linear_control 六种变体。它们分别保留原状态、去除冷却、增加 0.35 冷却额度、增加 0.12–0.35 并发负载、锁定一项分配、改为线性容量模型。

基础场景按预定索引均分为 broad、boundary、axis_stress 三个子集。随机方向的容量交点通过物理模型解析求解，再乘以 0.35–1.6 的随机比例；boundary 使用 0.94–1.06，axis_stress 将某个方向分量放大 8 倍。**边界样本是刻意覆盖决策边界的压力测试，不代表生产流量比例。** 生成器不调用几何或线性判断器，所有样本保留，没有按测试结果筛掉难例或打平例。

## 算法与公平性边界

所有表示共享确定性特征 load=(b+Lq)/R、credit=c/R 以及任务约束。几何调用现有 clafr 的 RiskBudgetCone、FeasibleRegion；使用新增的确定性 lifting，未调用生产语义编码器或 PolicyCompiler。

对照包含学习的单个仿射分数，以及 1 / 4 / 16 / 64 个半空间组成的多面体。半空间法使用与几何相同的负载和冷却坐标，法向量在训练方向上用覆盖初始化和球面聚类拟合；不限制成弱的单字段阈值。它是明确的有限线性表示类，未声称求得全局最优的 K 面多面体或最优仿射分类器。

每种线性表示同时保留两个开发集校准规则：weighted 最小化 5×误放率+误拦率；safety_1pct 在开发集误放率不超过 1% 的条件下最大化安全放行。两者均在**原始开发动作**上校准，没有用测试或修复候选重新调阈值。开发集安全率也不保证测试或修复动作安全率。线性控制场景对几何和线性基线均使用已知的精确线性法则，用于执行一致性检查，不用于声称学习泛化。

修复流程对所有表示相同：未锁定的动作按 1、0.99、…、0 等比例缩放，只保留满足任务约束的候选，选择第一个通过本表示的动作。锁定项不能改变。成功上界由独立模拟器枚举**同一个有限候选集合**得到；不是全空间最优解，也不是原生 DAFR 修复器的性能证明。所有返回动作均经模拟器复核，越界动作记为失败，不把模型判定安全当成执行安全。

等价的非线性算术规则作为必备控制组，与几何应当完全一致。允许规则使用平方特征或任意非线性谓词后，本实验不能证明几何判断优于这些等价表示。

## 冻结、选择与统计

先在开发集检查几何精确性，以及相对学习线性与 4 面多面体的 balanced accuracy 差距至少为 5 和 2 个百分点，达标后保存模型、源码和数据 SHA256，再评估测试。该流程是已披露的设计探索门槛，**不是外部预注册**；不因看到测试结果而修改模型阈值。

公开算法输入为 *_inputs.jsonl，不含安全标签、场景类别、变体名称或分组标识。*_labels.jsonl 与完整 evaluator 文件分开保存。原始 JSONL 是评测器资料，不应直接作为模型提示输入。标签分离防止直接泄漏，并不意味着模型不知道公开的物理法则。

置信区间按 120 个基础测试场景做配对 group bootstrap（2,000 次），不能把配对变体或同一场景的修复候选当成独立样本。

## 冻结测试结果

下表全部使用 weighted 校准，避免混用每行最有利配置。二次场景有 353 条不安全、247 条安全原动作；有限修复语法中 481 条场景可完成任务。

| 表示 | 原动作误放 | 原动作误拦 | 安全且完成任务 | 返回的越界动作 |
|---|---:|---:|---:|---:|
| 1 个联合风险锥 | 0 | 0 | 481/481 | 0 |
| 等价非线性算术 | 0 | 0 | 481/481 | 0 |
| 学习仿射规则 | 2 | 61 | 418/481 | 18 |
| 1 个线性半空间 | 0 | 49 | 430/481 | 25 |
| 4 个线性半空间 | 2 | 15 | 460/481 | 16 |
| 16 个线性半空间 | 0 | 2 | 470/481 | 11 |
| 64 个线性半空间 | 0 | 3 | 480/481 | 1 |

几何相对学习仿射规则的原动作准确率提升 10.5 个百分点，95% 配对区间为 [7.67,13.33]；相对 4 面约束提升 2.83 个百分点，区间 [1.17,4.83]。相对 16 / 64 面约束的原动作差距区间包含 0，不能称其决策准确率显著更差。

必须保留的反例：64 面 safety_1pct 配置在原动作上与几何打平（误放=误拦=0），但返回了 35 个越界修复动作，仅完成 446/481 个可恢复任务。这表明原始动作准确率无法保证编辑后的动作安全，并非几何在所有静态数据上都必胜。两种校准配置均在完整 report.md 中报告。

| 单因素消融 | 原动作误放 | 原动作误拦 | 安全且完成任务 | 返回的越界动作 |
|---|---:|---:|---:|---:|
| 去掉联合预算，改为各通道独立上限 | 204 | 0 | 247/481 | 328 |
| 去掉跨通道混合项 | 136 | 0 | 247/481 | 299 |
| 去掉冷却额度 | 0 | 153 | 326/481 | 0 |
| 用规划时旧负载替代当前状态 | 118 | 0 | 247/481 | 305 |
| 去掉修复 | 0 | 0 | 247/481 | 0 |

这些消融支持本模拟器中的五个机制贡献，不替代完整 DAFR 的 evidence、lifting、dynamic geometry、decision repair 模块消融，也不覆盖所有模块交互。无修复组的判断与完整组相同，但任务成功数不同，所以不能仅用判断准确率评估修复。

## 复现与文件

依赖 Python 与 numpy。仓库根目录运行：

```powershell
python scripts/run_geometry_capacity_benchmark.py
python tests/test_geometry_capacity.py
python scripts/audit_geometry_capacity_benchmark.py
```

结果位于 results/summaries/geometry_capacity_v1。report.md 包含全部配置；summary.json 包含分层结果和配对区间；test_rows.jsonl 包含逐样本判断、实际输出与执行违规；candidate_audit.json 检查冻结哈希、分组不泄漏、全部已声明修复候选、线性批量实现与原生几何组件逐项一致，以及可复核的越界见证。

数据可保留作几何表示的受控证据。若用于论文，应明确声明生成法则、边界采样、已知物理模型和有限线性表示类，不能把这些结果写成真实环境验证或“几何优于任何规则”。

## 全候选复核结果

上述审计已通过，涵盖二次测试场景的 24,586 个任务合法候选，其中 15,603 个执行安全、8,983 个执行不安全。每个线性候选的批量判断均与原生 LinearFacet 判断逐项一致，排除了批量实现差异。原始测试输出也已逐一重新执行核对。

| 表示（weighted） | 候选误放 | 候选误拦 |
|---|---:|---:|
| 联合风险锥 | 0 | 0 |
| 等价非线性算术 | 0 | 0 |
| 学习仿射规则 | 120 | 2,411 |
| 4 个半空间 | 24 | 587 |
| 16 个半空间 | 12 | 97 |

64 面 safety_1pct 对原动作完全正确，但在相同预声明修复候选中有 35 个误放，影响 28 个基础场景。候选指标仅描述覆盖情况，不以 24,586 为独立样本数计算显著性。

## 原版 DAFR 接入回放：未通过完整方法验证

随后实际运行了生产 CLAFRToolsExecutor，不增加容量特征、容量编译规则或数值修复。使用真实 FunctionsRuntime 注册读状态与更新分配工具，先读状态再提出冻结动作。四个生产模块开关共 16 种组合，另加 halfspace_only 与 cone_only，共 18 种配置；全部运行 720 条测试场景，共 12,960 次场景配置评估。

二次容量子集上，所有配置结果相同：353/353 个不安全原动作被转发给工具，247/247 个安全原动作被转发；成功完成 247/481 个在公共候选语法下可恢复的任务，数值修复为 0。模拟器拒绝越界更新，所以这些是防御未拦截的调用，不是环境实际提交了不安全状态。线性控制子集同样未识别容量越界。

完整配置确实经过生产 45 维编码和 14 个约束（含现有风险锥）；问题不是组件没运行，而是这些语义特征与约束不表示该数值容量法则。原生 repair 删除未授权的可选字段，不能通过修改必填 allocation 数值恢复任务。

因此，上面的 481/481 是新增容量 lifting 和公共候选枚举下的几何机制结果，不能归因于原版 DAFR。原版回放结果否定了将本批数据直接作为完整 DAFR 正向消融的做法。此次回放固定上游动作，没有新 LLM 规划、反馈后重规划或最终回复投影，也不能称为完整智能体端到端实验。
